# SpacemiT K3 llama.cpp Benchmarks

Inference throughput on the SpacemiT K3 (Muse Pi / BPI-F3 class) RISC-V SoC, comparing four
llama.cpp builds across the Gemma 4 and Qwen3.5 model families. All runs use the 8 A100 AI
cores (`cpu_mask: ff00`, IME2 matrix instructions, `use_ime2: 1`) at 2.0 GHz
(`performance` governor).

Generated by [`bench_matrix.sh`](bench_matrix.sh) from [`results_bench.tsv`](results_bench.tsv)
and [`results_mtp.tsv`](results_mtp.tsv). Figures are t/s; `pp` = prefill (prompt), `tg` = generation.

## Builds compared

| Build | What it is |
|---|---|
| **Bianbu 4.0.1 (0.1.1)** | The `llama.cpp` shipped in the Bianbu system image (apt) |
| **SpacemiT 0.1.3** | SpacemiT's official `spacemit-mtmd` release tarball |
| **Platima llama-smt** | This fork: SpacemiT base + Gemma 4 MTP merge + fixes |
| ~~upstream b9628~~ | *Excluded:* vanilla upstream + SpacemiT flags heap-crashes on the prefill→generation transition (reproduced on b9628 and a fresh build). The SpacemiT backend carries an un-upstreamed fix. |

## 2. Multi-Token Prediction (MTP / speculative decoding)

**This is where the fork is unique.** Only `platima-llama-smt` runs Gemma 4 MTP at all, and
it roughly doubles Qwen MTP throughput versus SpacemiT 0.1.3. MTP figures are the mean of
5 × 256-token runs, FA on.

### MTP availability & throughput by build (FA on, tg/s)

| Model | Bianbu | SpacemiT 0.1.3 | Platima llama-smt |
|---|---|---|---|
| `Qwen3.5-2B-Q4_1-MTP` | ✗ | 7.00 | **12.18** |
| `Qwen3.5-4B-Q4_K_M-MTP` | ✗ | 4.70 | **8.40** |
| `Qwen3.5-9B-Q4_K_M-MTP` | ✗ | ✗ | ✗ |
| `gemma-4-E2B-qat-MTP` | ✗ | ✗ | **13.90** |
| `gemma-4-E4B-qat-MTP` | ✗ | ✗ | **12.00** |
| `gemma-4-12b-MTP` | ✗ | ✗ | **4.00** |
| `gemma-4-12B-qat-MTP` | ✗ | ✗ | **6.00** |

✗ = flag rejected or model architecture unsupported by that build.

### MTP speedup vs base (Platima llama-smt, FA on)

| Model | Base tg/s | MTP tg/s | Speedup |
|---|---|---|---|
| `Qwen3.5-2B-Q4_1-MTP` | 16.06 | 12.18 | 0.76× *(net loss)* |
| `Qwen3.5-4B-Q4_K_M-MTP` | 7.10 | 8.40 | 1.18× |
| `Qwen3.5-9B-Q4_K_M-MTP` | 4.23 | OOM (base+draft, 16 GB limit) | — |
| `gemma-4-E2B-qat-MTP` | 13.29 | 13.90 | 1.05× |
| `gemma-4-E4B-qat-MTP` | 7.81 | 12.00 | **1.54×** |
| `gemma-4-12b-MTP` | 3.08 | 4.00 | 1.30× |
| `gemma-4-12B-qat-MTP` | 3.55 | 6.00 | **1.69×** |

**Reading the speedup:** MTP wins biggest on the slower, larger Gemma models (E4B **1.54×**,
12B-QAT **1.69×**) where accepted draft tokens save the most wall-clock. It is marginal on the
already-fast small models, and a **net loss on Qwen3.5-2B** (the DeltaNet draft overhead isn't
recovered when the base is small and fast). Qwen3.5-9B MTP **OOMs** — base + draft + KV exceeds
16 GB.

## 3. Practical takeaways

- **Best multimodal daily driver:** `gemma-4-E4B-it-qat` + MTP → **~12 t/s**, image + audio in,
  fits comfortably in 16 GB. The 1.54× MTP lift turns a marginal 7.8 t/s into a usable speed.
- **Best text quality that fits:** `gemma-4-12B-it-qat` + MTP → 6.0 t/s (1.69× lift).
- **Fastest small model:** `Qwen3.5-2B` at 16 t/s base — but skip MTP on it (net loss).
- **QAT beats plain quants:** Unsloth `UD-Q4_K_XL` (QAT) edges Google's `q4_0` on both E2B
  (13.3 vs 12.1 tg) and E4B (7.8 vs 7.0 tg).
- **Avoid `UD-Q4_K_XL` on Qwen3.5 (DeltaNet):** mixed-precision XL craters prefill to ~10 t/s
  vs ~40 for plain `Q4_K_M`.

## Method

- Hardware: SpacemiT K3, 16 GB, 8× A100 cores @ 2.0 GHz, `performance` governor.
- `llama-bench -t 8 -p 128 -n 128 -mmp 0 -fa {0,1} -ub 128` for base throughput.
- `llama-cli --spec-type draft-mtp --spec-draft-n-max 4 ... --simple-io`, 5×256 tok mean, for MTP.
- Per-model cooldowns to avoid thermal drift; correct SpacemiT libs confirmed via `use_ime2: 1`.
- Full commands in the last column of each TSV.
